## Implementation acceptance boundaries

These are already required by the proposal, not blockers or added features:

1. Keep the ten-object/ID reservation before either private split. A final-validation-only seam overflow would roll back, but would not meet the specified early reservation.
2. Keep unchecked `CutPiece` byte/ID/history behavior and original fixtures exact. Reuse existing test helpers; extend them only where the sewn case needs independent stitch checks.
3. Keep the checkbox in the preview key and keep its interactions separate from acceptance. The current modal captures Return before rendering its controls (`main.rs:3559`), so checkbox keyboard interaction must be checked explicitly alongside opening-Return and one-Apply tests. Preserve text widget identity/caret while refreshing the cloned preview.
4. Inspect the actual retained Cloth slice through the one read-only getter. Do not substitute a newly reconstructed input, UI line, seam count or successful constructor for the stipulated weight, endpoint, coverage and per-owner mass checks. Ordinary `CutPiece` must still retain zero stitches.
5. Run the four required local Rust gates only after an approved implementation in a new isolated worktree with its own Cargo target. Keep truthful source/native/reference distinctions and publish only tracked evidence after clean-checkout registry/map checks.
