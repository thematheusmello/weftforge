## Capability gaps that the plan cannot honestly close

Documented CUA provides a complete `drag(from,to,options)` call, with no steps,
duration, held-state, separate down/up or keyboard-mid-drag control. A returned
call plus post-state can show a completed gesture, not intermediate press/blur
or cancellation delivery. A prior real drag returned without a revision; cause
remains unknown. The titlebar/content-Y subtraction is a prospective hypothesis,
not calibrated delivery. Each planned drag has one chance and no numeric rescue.

The existing original native driver manifest has only whole click/drag actions,
no keyboard-between-down/up mode, and fixed identity guards for another app. It
cannot be used on WeftForge unchanged, and this preparation does not authorize
adapting or running it. No new software/setup is proposed.

Consequently the full native gate still requires supported native input for
separate press/release, Escape/history during a held endpoint drag and strict
same-frame AX-focus+Apply. Ordinary Tab, observed field focus, unfocused Return,
modal background attempts and complete pointer actions remain independently
testable. A visible screenshot is evidence for a modal field absent from AX;
there is no invented accessibility pass.

The prior unexecuted transform B2 is not retroactively passed by B's numeric
transform. If superseding that pointer scope is required now, add a separately
reviewed sixth case with its original snapped translation and 43–47 degree
rotation math, updated for strict v4 and internal endpoints. It would add about
60 calls/600 seconds and retain the unknown coordinate-origin gap.
