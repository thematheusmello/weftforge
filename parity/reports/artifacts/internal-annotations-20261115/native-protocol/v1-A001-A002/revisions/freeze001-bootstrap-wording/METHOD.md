## Native protocol and raw saves

PLAN.json has the complete ordered case procedures, exact original numeric
literals, names, revision expectations and macro maxima. STATIC-BUDGET.json counts
all launch/bootstrap/input/observation/wait/file-copy operations, not only authoring.
Every API operation has a before/returned UTC+monotonic pair. The external raw-copy
operation is also paired into that filesystem counter. Completion_summary has one
separate before/returned tool receipt and is one extra CUA call per case.

After every field focus, text input or Tab: capture and inspect the original raw
AX+screenshot before the next input. Never batch input speculatively. Use only
observed target coordinates/indices, including observed inspector scroll bounds.
Modal fields absent from AX are tested visually; absence is not an AX pass.

For each Save As/export chooser, locate the current observed editable/settable
Name field. Call documented setValue ONCE with the literal basename. Capture the
exact basename and enabled Save, then click Save once. No hardcoded AX index,
keyboard filename fallback, alternate chooser or repair. One documented Go To
Folder path is allowed if the observed current directory is not the exact owned
location. File > Save is the observed native route for subsequent accepted states
of the same mutable primary. No repeated Save As dialog is needed for history.

After each observed clean Save, retain exact primary bytes with:

`python3 retain_saved.py copy --run CASE_DIR --case A --label A03-edited --save-record NNNN --capture-record MMMM`

Use the case's actual planned label and returned records. The helper copies raw
bytes without parsing or grading construction during the native input lease. It
refuses overwrite, marks snapshots read-only, records source Save/capture IDs,
planned observed revision, primary/snapshot SHA and sidecar hashes. Native recovery
must equal exact previous-primary raw bytes; it is never regenerated JSON.
Inventory own primary/autosave/recovery files before/after, with size/hash and
revision where parseable after closure. Retain own PID-specific untitled/exit
sidecars if produced. Existing unrelated recovery entries are not opened, copied
or counted as this case's output. Autosave can legitimately be older than current
construction; keep its revision/staleness visible instead of expecting no sidecars.

The raw SVG/OBJ before/after bytes must agree. Each raw DXF must have exactly one
group999 own-revision comment (2 or3); normalize only that validated value in
memory and keep all other bytes exact. The grader also checks original closed C
SVG path/units and DXF exterior geometry/layer/units, and rejects OBJ annotation
line primitives. OBJ comparison proves annotation invariance, not an independently
correct absolute meshing algorithm. Keep rest output/preview/cloth distinct.

## Stop, closure and independent grading

Any unexpected/ambiguous barrier, exception, wrong revision/identity, unavailable
required target, elapsed/call cap or missing file stops that case unverified.
The very next CUA call must contain only completion_summary exactly once. No
further input, observation, save or quit is permitted inside that failed case.
Planned invalid-input refusal/correction is part of the procedure, not rescue.
No retry, numeric drag substitute, fixture edit, output repair, relaxed criterion
or old-result regrading is allowed.

On success one planned quit is the final native observer. Accept only the
prebound documented expected close/termination outcome. Do not inspect AX or call
getApp on the closed target. The next CUA call is completion_summary only, once.
Postflight hashes/PID accounting are outside CUA. If an owned failed-case app is
left open, any later cleanup is separately documented after outcome/summary and
does not repair or continue the old case.

After native input closure, root writes NATIVE-LEASE-CLOSED.json and performs the
one formal saved-file grade, retaining a failed/missing-output result as-is:

`python3 grade_saved.py grade --case A --run CASE_DIR --report FRESH_REPORT.json`

FREEZE.json pins the prospective packet and grants no execution. A separate
root final runtime binding and GO are mandatory after final metadata verification;
no actual runtime binding or GO exists here. The grader returns `native_ui_verified:false` even on
passing saved data. Root separately reviews every native trace and unedited image
for the actual routes, focus/caret/rendering/preview/history and omission help.
All original/derived artifacts must later be Git-tracked and registry/map checks
run from a clean checkout before any delivery/publication claim. Ignored local
preparation is not delivery.

## Explicit native gaps

It cannot witness held-drag Escape/history, intermediate press/blur suppression,
or strict same-frame AX-focus+Apply. Sequential Tab/capture/Apply, actual observed
focus, unfocused Return, modal background pointer/shortcut attempts and a complete
drag are narrower observations. A background AX authoring node that is absent or
not actionable cannot be reported as tested. Record these exact gaps.

current raw screenshot/content boundary and record both raw and transformed
endpoints. With the old geometry the hypothesis was32px; do not reuse old pixels

not establish OS delivery. If one planned drag fails, stop without retry/rescue.
Strict fixed1000px/m native mapping and Alt-click bypass are not established by
these cases; saved construction still has its exact prospective targets.

The read-only original-driver manifest review found only atomic click/drag actions,
no keyboard-mid-drag control, and hardcoded identity guards for another app. It
was not executed or adapted. No supported native driver currently closes the
held-state gaps, and no new setup is proposed.
