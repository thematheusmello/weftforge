# Independent transform acceptance, frozen before candidate execution

This is implementation acceptance under the approved WeftForge layout policy. Reference behavior remains unobserved. No candidate outputs were read when preparing these files.

The scope is the immutable native-v3 fixture, declared success/rejection cases, CLI `execute`, current and legacy MCP `project_execute`, independent JSON/geometry/grain/metric checks, and one fresh mesh inspection per route. The root agent owns native events, pending drafts, undo/redo, stale cloth rejection, integrated Cargo gates and publication. The file format does not persist history; this runner checks one success revision and exact IDs/maps/allocator, not nonexistent adapter undo.

The acceptance math below uses an explicit independently multiplied Rz*Ry*Rx matrix, the analytic parabola and its length primitive; no production helper is imported or called by the grader.

`fixture.weftforge` is original authored data. Its selected endpoint includes negative zero deliberately, so the zero-axis translation check is sensitive to bit loss. Sewing includes reversed partial intervals, a gap, nonidentity maps and an untouched second piece. Colors are exactly representable f32 values. Variant rows modify only the declared selected placement, grain, or dyadic offset; they never repair candidate failures. Output gimbal rows use original X rotations near +/-pi/2 and a quarter-turn layout rotation, deliberately forcing singular or near-singular compensated orientations. Input gimbal rows test the converse. The 32-epsilon branch is disclosed by the reviewed contract; acceptance compares represented matrices rather than the chosen Euler representation.

The script self-check is required before freeze. It must accept a synthetic analytic quarter-turn and reject wrong rotation order/sign, unchanged placement, naive Z-only compensation on a tilted piece, unchanged grain, millimetre coordinates, changed sewing maps and extra revision increments. It also checks the non-right-angle inverse and the control-only overflow precondition. These synthetic documents are evaluator tests, never candidate evidence.

The runner requires a root-supplied binding JSON with `authorized: true`, exact `source_commit`, `binary`, `binary_sha256`, and `root_reviewed_freeze_sha256`. It verifies every frozen file before invoking the binary, refuses to overwrite a run directory, records byte retention, and rechecks the binary and frozen inputs afterward. No candidate invocation is authorized merely by generating this packet. Run later with `python3 evaluate.py run candidate-binding.json`.

On success, the runner deliberately seeds a valid old output and a distinguishable recovery file. It expects output replacement and exact old-primary recovery. It still requires read-only input primary/recovery, commands, and unrelated files to retain exact bytes. Rejections must retain both destination files. A candidate rejection of the original fixture is a precondition failure, not an invitation to modify the fixture. The runner records failures and never widens criteria or auto-retries a changed fixture.

Skipped: reference observation, native UI/history, typed NaN/infinity API tests, stale cloth API test, Cargo, source modifications and publication. Risk: this local packet is not delivery until the root tracks its evidence and verifies registries/maps from a clean checkout.
