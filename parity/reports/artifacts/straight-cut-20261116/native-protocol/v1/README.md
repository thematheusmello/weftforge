# R240 native acceptance preparation

Prospective private packet only. No native lease, GO, source/GUI/product run, actual-case
assessment, parity credit or full-feature acceptance is provided here. The immutable
approved-v2 CONTRACT/ORACLE/NATIVE-R and both original fixtures stay authoritative.
This packet does not rewrite that procedure or replace its actual-empty CUT-R1 origin
or CUT-R2's accepted actual R4 dependency. Concave and failed-I/O native acceptance
remain separate required work. The known .005 fine-mesh vertex-cap limitation is
outside these two native cases and stays visible.

Scope reaches the saved-file grader, opaque raw-byte retainer, synthetic checks,
binding/closure templates, current native label notes and the immutable observer
callsite. There are no source, command/schema, Cargo, public evidence or Git changes.
The old A–E whole-case grader/preflight is incompatible. Only its pinned strict JSON,
file/bit/exact comparison helpers are imported, with bytecode writing disabled; the
retainer reuses its narrow fsync/read-only raw-copy pattern. Neither old file changes.

`grade_saved.py` constructs assessment-only models in memory from the original
literal R240 fixture and ORACLE allocation/incidence/walk recipes. It never imports
product code, geometry, parsers or binaries as an expected-answer engine. It compares
complete v4 structure and defaults, ordered IDs/lists, revisions and allocator values.
Unchanged authoring uses exact f64 bits (including signed zero); color uses f32 bits.
Only the four new cut endpoints get the original 1e-12m coordinate measurement budget.
Copied endpoints must be bit-identical to their anchors. R4 is exact actual R2 except
revision. R5 is exact accepted actual R4 except revision and the declared two y edits
within 1e-12m; its unchanged x values stay bit-exact. Directed walks, independent
ownership, analytic areas, perimeters and material area×density are measured with
stdlib arithmetic. This is not solver-particle mass, mesh, export, UI or parity proof.

`retain_saved.py` copies opaque native bytes only after the observed clean save.
It retains every primary and sidecar/absence separately, makes copies read-only,
records the actual Save/capture/current FS operation, and never grades construction
during the input lease. Parent→cut→undo→redo recovery must be exact previous-primary
bytes. Original work/recovery files remain in their owned work directory too. The
initial SaveAs destinations must be fresh; no earlier recovery is accepted there.

After the clocked actual CUA proof, owned launch/PID, native case, immediate summary
and input closure, root may run exactly one formal command per attempt:

```text
python3 <packet>/grade_saved.py --case CUT-R1 --run <owned-run> --report <owned-run>/SAVED-GRADE-001.json
```

CUT-R2 uses its own run and `--case CUT-R2`. There is no formal selfcheck flag and no
live-data grading mode. The exact `NATIVE-LEASE-CLOSED.template.json` schema must
exist first. Then the grader atomically creates `SAVED-GRADE-ATTEMPT.json`; any grade
failure remains final for that attempt. Missing output fails. Root separately reviews
raw native images/traces before accepting a case. No repair, retry or regrade of an
earlier case is permitted. Synthetic testing called only in-memory/model/receipt
functions on temporary fabricated files, not this formal entrypoint.

For each clean save, root wraps the following invocation in the one counted
`fs.raw_snapshot` recorder operation; `<copy-id>-before.json` already exists and
the matching returned record is written after the helper returns:

```text
python3 <packet>/retain_saved.py --case CUT-R1 --run <owned-run> --label parent-r1 --save-record <save-id> --capture-record <clean-capture-id> --retain-record <copy-id>
```

The expected revision in its receipt is a declared label, not a live document read.
Root must visually establish clean save/revision before the copy. The formal grader
later checks the actual snapshot revision. SAVE clicks use the observed File route;
SaveAs uses one currently observed settable Name field, one setValue, one capture
showing the literal basename and enabled Save, then one Save. There is no keyboard
filename fallback, repair, stale index or alternative chooser.

The frozen synthetic checks cover 33 model/provenance/closure mutants and exact raw
copies. The Node observer check uses mocks in separate vm contexts and proves only
explicit controller/app/label/marker/output arguments. It is **not actual-CUA proof**.

Before GO, root still binds the integrated source69 inventory and clean metadata,
all local gates, exact fresh own bundle/binary/hash, OS/runtime target identity,
no-input argv for CUT-R1 or accepted actual read-only R4 argv for CUT-R2, controller
configuration, artifact paths and separate exclusive lease. There is deliberately
no executable launch script or staged native input in this packet. Runtime CUA
capabilities, native focus/caret, view/selector accessibility, actual save chooser and
native rest-mesh readiness remain unobserved barriers; stop at the first ambiguity.

`PLAN.json` preserves static158/cap175+one summary/1200s and static49/cap65+one
summary/600s. Every clocked bootstrap, FS, launch, input, wait, capture and quit is
counted. Required documentation refresh after compaction is separate counted
bookkeeping within the same total cap/reserve and continuous clock, never hidden.
The filesystem UTC+monotonic clock begins before the first standalone fresh CUA
getState, import proof, external launch, owned-PID check, getApp or capture. Start12
is unchanged. Clock/trace bookkeeping is inside its operation envelopes; any
additional case-relevant FS operation consumes reserve rather than changing static
counts. Root must not restart the clock at controller construction or app launch.

Use the pinned 393-byte observer with all five actual arguments. Its marker exists
synchronously before any observation and never reads a future app binding. Fresh
screenshots/AX determine clicks; this plan has no drag or titlebar-origin adjustment.
On success the one planned real Quit is the last native observer, and the **very next
tool call** is summary-only CUA completion_summary exactly once. On any failure the
next CUA call is summary-only, with no extra observer/input/Quit. No timestamp or
other tool intervenes after the terminal outcome. Store conservative conditional
lower markers during the case; only the applicable last marker and later returned
summary receipt bound the summary. Neither is an exact invocation timestamp or
native API pair. Raw retention precedes cleanup; any leftover owned window cleanup
is separate later work and cannot alter the frozen case result.

No code beyond this private packet was changed. Cargo, GUI, native, CLI, evaluator,
remote, source69 registry/map and clean-checkout publication checks were not run here.
