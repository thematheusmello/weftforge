simulation off. Activate `2D Pattern > Create > Rectangle`; the toolbar exposes
`Rectangle (S)`, checked. One left click in the empty 2D canvas opens **Create
Rectangle**, consistent with the [official Rectangle manual](https://support.marvelousdesigner.com/hc/en-us/articles/47358203451673-Rectangle).
The actual native pointer driver was needed for this canvas gesture. No target

## Executed original scenario

1. Enter `200` in Width through keyboard replacement and commit with Tab. Width
   becomes 200 mm while Height remains 500 mm; replicate interval becomes 300 mm.
2. Enter `300` in Height and commit with Tab. Height becomes 300 mm; Width and
   replicate interval remain 200 and 300 mm. The dimension link stays off and
   shape count stays 1. No general replication formula is inferred from this pair.
3. Click OK. One rectangle with four visible corner handles appears in both
   views. The selected boundary reports **1000.0 mm** in both 2D Line Length and
   3D Line Length, consistent with `2 × (200 + 300)` mm.
4. Execute one `Edit > Undo`. The shape disappears and the entire retained REA
   window record matches the known empty pre-creation state. Execute one
   `Edit > Redo`: the rectangle and the same 214-node AX property state return.
   Screenshot hashes differ, so pixel identity is not claimed.
5. Save to a new private `reference-rectangle-200x300.zprj`, then use
   `File > New Project` to close that document and observe an empty untitled one.
6. Use `File > Open > Project` to reopen the saved file, then `Edit > Select All`
   to inspect the reopened rectangle. Its generated pattern name, both 1000.0 mm
   boundary totals and 20 mm particle distance are retained. The native file's
   SHA-256 is unchanged by reopening. This tests document close/open, not process
   quit/relaunch.

The initial selected pattern also exposes particle distance **20 mm**, grain
direction 0 and layer 0. Their accepted ranges and edit semantics are separate
observations; no simulation was executed in this scenario.

file existed. A subsequent Proceed allowed saving the new research file. Opening
it showed the same warning twice, then completed after the two Proceed actions.
These warnings concerned only the investigator's disposable original document;
no unrelated user document was opened or overwritten.

## Independently measured original export

After reopening, export the original rectangle through `File > Export > OBJ`.
Observed options are **100%**, **mm (Default)**, X / Y (Up) / Z with no axis
inversions, Thin, Unweld, Single Object, all patterns selected, no hidden/internal
objects, no proximity merge and no metadata XML. The visible dialog title is
Export OBJ while its AX dialog title is Import OBJ; the executed route was export.
No export option was changed in this run.

The [reviewed measurement record](../observations/REF-PAT-003-RECTANGLE-001-pd20.json)
pins the exported file and the [independent evaluator](../evaluators/original_obj_bounds.py).
It contains 290 vertices and 525 triangles. The parser reads plain OBJ geometry;
expected dimensions come from the typed constructor values, and units come from
the observed export control. It does not normalize the mesh to fit expectations.

Measured extents are **200.000015 × 300.000122 mm**, with 0.000030 mm near-planar
thickness noise. Maximum dimension error **0.000122 mm** passes the predeclared
**0.01 mm** tolerance. Convex-hull perimeter is 1000.0000000002 mm and area is
60000.01445 mm². The floating-point hull has six vertices; exact four-vertex mesh
topology is not inferred from it. Interior topology and cloth physics are not
validated by these dimension measurements.

An additional [independent boundary review](../observations/REF-PAT-003-RECTANGLE-001-pd20-boundary.json)
checks this same retained OBJ against the declared rectangle. All 290 vertices
are used; 53 boundary edges form one loop, interior edges have incidence two,
projected triangle winding is consistent, and Euler characteristic is one.
Maximum boundary error is 0.000122 mm against the fixed 200 × 300 mm expectation.
These are bounded mesh checks for this original export, not a general polygon
intersection or cloth-physics proof. A synthetic rectangle mesh with an interior
hole passes physical extents but fails the boundary check; reversing one triangle
also fails. No additional reference UI action was needed for this offline review.

A controlled copy with X extent changed to **1 mm**, while expected dimensions
and fixed units stayed unchanged, is rejected as expected. Three evaluator tests
cover known original dimensions, wrong physical scale and nonfinite coordinates.
Raw OBJ/MTL remains private; only original measurements and independently authored
measurement code are public.
